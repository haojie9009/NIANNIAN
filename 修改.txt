每次测试 调用大模型，都花费很多钱，评价下以下方案
 
1. 缓存 LLM 响应（Recorder/VCR 模式）
参考 vcrpy 或 pytest-recording 的思路：

第一次跑测试时真实调用 API（或本地 LLM），把响应序列化存到文件
后续测试直接回放缓存，零 API 消费
写一个 LLMCache 包装类，根据 (model, messages_hash) 作为 key

2. 抽离纯逻辑测试，不要每轮都调 LLM
把你的 Pipeline 拆成：

纯逻辑层：数据校验、字段提取、格式转换等 → 用 pytest 测，不依赖 LLM
集成层：仅 pipeline 定型后偶尔跑一次全流程
skill_loader.py、pipeline_runner.py 中有大量解析、格式化逻辑可以单独测试。

3. 加一个 DRY_RUN 开关
在 llm_client.py 开头加一个环境变量如 NIAN_DRY_RUN=1，所有 call_skill() / call_memorial_chat() 直接返回预设 JSON，跳过真实 API 调用。
