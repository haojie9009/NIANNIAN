# 念念（NianNian）追思影像平台 — 架构与优化建议

> 生成日期：2026-05-28
> 分支：dev-zm
> 状态：不修改代码，仅做审查与建议

---

## 一、项目概述

念念是一个 AI 驱动的追思影像生成平台，通过 AI 访谈引导家属收集逝者故事，自动生成分镜脚本、角色设定、最终合成纪念视频。项目已从 Streamlit 单体架构演进为 **FastAPI 后端 + 原生 JS 前端 + 遗留 Streamlit 调试工具** 的三层架构。

## 二、架构层面

### 2.1 严重单体文件（CRITICAL）

| 文件 | 行数 | 问题 |
|------|------|------|
| `backend/services/service_manager.py` | ~1580 行 | 包含 7+ 种职责：Pipeline 编排、深度搜索、纪念聊天、数字人、场景图片/视频生成、TTS、BGM、视频合成 |
| `backend/services/llm_client.py` | ~1834 行 | 包含 8+ 种职责：缓存、文本 LLM、视觉、语音转写、TTS、BGM、图片生成、视频生成 |

**建议**：按职责拆分为独立模块，例如：
- `services/pipeline.py` — MV 流程编排
- `services/scene_gen.py` — 场景图片/视频生成
- `services/audio.py` — TTS + BGM
- `services/video_assembly.py` — MoviePy 视频合成
- `llm/text_client.py` / `llm/image_client.py` / `llm/video_client.py` / `llm/audio_client.py`

### 2.2 存储层过于简单（HIGH）

当前使用文件 JSON/JSONL 存储（`data/users/`），无数据库。

- **并发风险**：`merge_dossier` 存在读-合并-写竞争条件
- **无事务保证**：写入中途崩溃可能导致数据不一致
- **不可扩展**：用户量增长后文件 IO 会成为瓶颈

**建议**：
1. 短期：在 `merge_dossier` 的读-写周期加锁（`_LOCK`）
2. 中期：引入 SQLite 或 PostgreSQL，保留 JSONL 作为对话审计日志
3. 会话存储（`session_store.py`）明确设计为可替换为 Redis，应提前规划

### 2.3 缺少 CI/CD 管道（MEDIUM）

- 无 GitHub Actions、无 Dockerfile、无自动化测试
- 部署仅依赖 `render.yaml`，`pip install` 无锁文件

**建议**：
- 添加 GitHub Actions workflow：lint → test → deploy
- 使用 `pip freeze` 或 `pip-tools` 生成 `requirements.lock.txt`
- 考虑 Dockerfile 保证本地/生产环境一致性

### 2.4 路由层缺少统一中间件（MEDIUM）

各路由重复 session 校验逻辑（`try/except KeyError → HTTPException(404)`），错误响应格式不统一（有的返回 `HTTPException`，有的返回 `{"error": True}` dict + HTTP 200）。

**建议**：
- 使用 FastAPI 依赖注入统一 session 校验
- 定义全局异常处理器，统一错误响应格式 `{ "error": { "code": "...", "message": "..." } }`

## 三、代码质量层面

### 3.1 安全问题（CRITICAL）

| 位置 | 问题 |
|------|------|
| `backend/core/security.py:7` | JWT 默认密钥为硬编码字符串 `"nian-dev-secret-change-me-in-prod"` |
| `backend/core/security.py:10` | 默认访问码为 `"666666"`，极易猜测 |
| `backend/services/service_manager.py:769` | freeimage.host API 密钥硬编码在源码中 |
| `backend/main.py:160-166` | CORS 通配符 `*`，生产环境未收紧 |
| 多个路由 | intake/chat/pipeline/dialogue 端点无需认证即可调用，会消耗 API 额度 |

**建议**：
- 生产环境强制要求设置 `JWT_SECRET`，无默认值
- 移除硬编码 API 密钥，统一放入环境变量
- CORS 改为可配置的白名单
- 对消耗 API 额度的端点添加 JWT 认证

### 3.2 代码重复（HIGH）

1. **LLM 重试/回退模式**：`llm_client.py` 中 5+ 个函数复制了相同的重试逻辑（播放缓存检查 → 模型队列 → 3 次重试 → 记录缓存），应抽象为 `_call_with_retry()` 通用函数
2. **Session 校验**：在 `chat.py`、`pipeline.py`、`dialogue.py` 中重复出现相同模式
3. **前端 bootstrap**：`memorial.js`、`dialogue.js`、`pipeline.js`、`studio.js` 各自实现了一套类似的 session 检查和状态恢复逻辑
4. **场景提取**：`_get_scenes_from_mv04` 函数存在，但 `run_pipeline_chain` 中又手动复制了一遍相同逻辑

### 3.3 错误处理不一致（HIGH）

- 多个 `except: pass` 静默吞掉异常（`storage.py:281`、`service_manager.py:138`、`llm_client.py:1527`）
- 业务错误返回 `{"error": True}` + HTTP 200，前端必须同时检查 `response.ok` 和 `data.error`
- 对话上传文件（`dialogue.py:48`）无大小限制，与 `uploads.py` 的 50MB 限制不一致

### 3.4 依赖管理（MEDIUM）

`backend/requirements.txt` 问题：
- 所有依赖使用 `>=` 无上限，可能拉入破坏性大版本
- **缺少 `moviepy`、`numpy`、`mutagen`** — 代码中有 import 但未声明
- `httpx` 声明了但代码中未使用（实际用的是 `requests`）

### 3.5 测试覆盖不足（MEDIUM）

**已有测试**：Gate Manager、Service Manager 部分函数、Session Store、API 基础集成
**缺失测试**：
- 大部分路由端点（auth、dialogue、pipeline、uploads、agent、voice、audio、admin、memorials）
- 完整 Pipeline 链（MV01→MV02→MV03）
- 视频合成（assemble_final_video）、TTS、BGM、场景生成
- `core/storage.py` 和 `core/security.py`
- 并发/竞争条件
- 错误路径（LLM 返回畸形 JSON、超时、空响应）

## 四、产品功能层面

### 4.1 用户工作流断裂（P0）

**两套独立的会话系统并行运行**：
- **Session-store 流程**（memorial.html → pipeline.html → studio.html）：使用 `niannian.session_id`，7 天过期，内存限 10 个
- **Memorial 流程**（library.html、index.html agent 聊天）：使用 `memorial_id` + 用户认证

Agent 可以创建 memorial 记录，但没有桥梁将其与 Pipeline session 连接。用户从 agent 聊天结束后无法自动进入 memorial 建档流程。

**建议**：统一 session 管理，让 agent 访谈结束后自动生成 memorial 并跳转到填写页面。

### 4.2 数据丢失风险（P1）

| 场景 | 问题 |
|------|------|
| 表单未自动保存 | `memorial.html` 表单仅在点击"下一步"时保存，浏览器崩溃/导航离开后数据丢失 |
| Session 7 天过期 | 用户可能超过 7 天才回来继续制作，无预警直接清空 |
| 10 个 session 上限 | 并发用户多时旧 session 被静默删除 |
| 多标签页冲突 | localStorage 共享 session ID，两个标签页操作不同步骤会互相干扰 |

**建议**：
- 表单添加 `beforeunload` 提醒 + 自动保存（debounce）
- Session 过期时间可配置，过期前发送提醒
- 考虑将 session 数据关联到 memorial 对象持久化存储

### 4.3 生成内容不可编辑（P1）

MV04 生成分镜后，场景描述、台词、角色外观都无法修改。技能文档描述了"部分循环"和"拒绝特定 scene_id"的能力，但前端没有对应 UI。

**建议**：在 `studio.html` 中为每个场景添加编辑按钮，允许修改描述后重新生成。

### 4.4 错误信息缺乏同理心（P1）

作为追思平台，用户多为悲伤中的家属，但错误页面直接显示原始 `<pre>` 技术信息（`pipeline.html:98-104`、`studio.html:141-146`）。

**建议**：
- 用户侧显示温和提示（"念念暂时遇到了一些问题，请稍后再试"）
- 技术详情折叠在"查看详情"中，仅供开发者使用

### 4.5 缺少"结束访谈"步骤（P2）

技术文档描述了结构化电话访谈含"结束访谈并生成文字稿"功能，但当前 agent 聊天是开放式对话，没有明确的终止和过渡点。

### 4.6 其他产品功能缺口

| 优先级 | 缺口 |
|--------|------|
| P2 | 无全局进度指示（跨页面显示"第 X 步 / 共 6 步"） |
| P2 | Library 无搜索、排序、筛选功能 |
| P2 | 无视频质量/分辨率选项（硬编码 1920x1080） |
| P3 | 无生成的纪念视频重新下载入口（library 中无法下载已生成视频） |
| P3 | 破坏性操作（删除 memorial）无撤销功能 |
| P3 | 登录页无"忘记密码"功能 |
| P3 | 测试数据按钮（memorial.html）在生产环境可见 |

## 五、可访问性与移动端

### 5.1 可访问性（P2）

- 步骤进度指示器缺少 `role="progressbar"` 和 `aria-label`
- 颜色对比度不足：`--muted-l: #8A7B6A` 在 `--bg: #F8F5F0` 上对比度约 3.5:1，低于 WCAG AA 的 4.5:1
- `studio.js` 中 `keydown` 事件监听器每次 `openLightbox()` 都会重复注册，导致累加

### 5.2 移动端适配（P2）

- 仅有一个 `640px` 断点，library 页面 `300px` 固定侧边栏在窄屏下占比过大
- 文件上传区不支持移动端拖拽
- 语音按钮的 `touchstart`/`mousedown` 事件可能在部分设备上双重触发

## 六、优化优先级建议

### 第一阶段（立即处理）

1. **移除硬编码密钥**，JWT_SECRET 强制要求环境变量
2. **收紧 CORS 配置**，改为可配置白名单
3. **为消耗 API 的端点添加 JWT 认证**
4. **补充缺失的依赖声明**（moviepy、numpy、mutagen）
5. **依赖版本上限**，生成 lock 文件

### 第二阶段（1-2 周）

1. **拆分 service_manager.py 和 llm_client.py**
2. **抽象 LLM 重试/回退通用函数**
3. **统一错误响应格式**
4. **表单自动保存 + beforeunload 提醒**
5. **错误信息用户友好化**

### 第三阶段（2-4 周）

1. **统一 session 系统**（agent → memorial → pipeline → studio）
2. **添加"结束访谈"和分步引导**
3. **实现场景编辑功能**
4. **全局进度指示器**
5. **补充关键测试覆盖**（路由、安全、存储、错误路径）
6. **搭建 CI/CD 管道**

### 第四阶段（长期）

1. **引入关系型数据库**替换纯文件存储
2. **Session 存储迁移至 Redis**
3. **移动端全面适配**
4. **可访问性合规**（WCAG AA）
5. **Library 搜索/筛选/排序**
6. **视频质量选项**
