## 二、CRITICAL 级别问题与优化方案

### 问题 1：硬编码密钥（security.py 第 7、10 行）

**现状：**
```python
JWT_SECRET = os.getenv("JWT_SECRET", "nian-dev-secret-change-me-in-prod")
OWNER_ACCESS_CODE = os.getenv("OWNER_ACCESS_CODE", "666666")
```

**风险：** 生产环境未配置环境变量时，攻击者可伪造任意用户/owner 的 JWT token，或直接用 `"666666"` 登录为管理员。

**优化建议：**
1. 移除默认值，环境变量缺失时直接 `raise RuntimeError` 拒绝启动
2. 新增 `backend/core/config.py`，集中管理所有配置项，启动时做完整性校验
3. Owner access code 改为数据库存储 + 一次性使用 + 可重置机制
4. `.env.example` 提供模板，`.env` 加入 `.gitignore`

### 问题 2：6 个路由模块完全无认证

**现状：** 以下模块的所有端点均未做任何认证检查：

| 模块 | 前缀 | 暴露能力 |
|------|------|---------|
| `intake.py` | `/api/intake` | 提交/读取表单、深度搜索 |
| `chat.py` | `/api/chat` | 生成对话、运行 pipeline |
| `pipeline.py` | `/api/pipeline` | 11个端点：运行步骤、生成图片/视频、角色/场景 |
| `assets.py` | `/api/assets` | 上传/下载/列出文件 |
| `dialogue.py` | `/api/dialogue` | 数字人对话状态、persona 更新 |
| `audio.py` | `/api/audio` | TTS、BGM 生成 |

**风险：** 任何未登录用户（或恶意爬虫）可以读取/篡改任意 session 的完整数据，消耗 LLM 算力，生成内容。

**优化建议：**
1. 为上述所有路由添加 `Depends(get_current_user)` 或 `Depends(get_current_user_optional)`
2. 使用 `get_current_user_optional` 的场景（允许未登录体验但数据不持久化），需在文档中明确标注
3. 建议在 `backend/middleware/auth.py` 中创建统一的路由级别 auth 中间件，按路由前缀批量应用
4. 短期方案（最小改动）：在每个 `@router.get/post` 装饰器下加 `current_user: dict = Depends(security.get_current_user)` 参数

### 问题 3：Session 存储无用户归属（session_store.py）

**现状：**
- Session 以 UUID 为唯一 key，文件存储在 `data/sessions/{sid}.json`
- `create_session()`、`get()`、`require()`、`update()` 均不接受也不校验 user_id
- Session 内容包含表单数据、聊天记录、pipeline 状态、数字人人设、音频配置

**风险：** 知道 session ID 的任意用户可以完全读取、修改、删除该 session 的所有数据。

**优化建议：**
1. **Session 结构增加 `user_id` 字段**：`create_session(user_id)` 写入归属
2. **读取时校验**：`require(sid, expected_user_id)` 验证归属，不匹配则抛 403
3. **存储目录改造**（可选，更安全）：`data/users/{user_id}/sessions/{sid}.json`
4. 对已有存量 session，做一次性迁移脚本，将无 user_id 的 session 标记为 "anonymous"
5. Admin 路由仍可按 owner 权限访问所有 session（保持现有行为）

### 问题 4：静态文件挂载无认证（main.py 第 200-204 行）

**现状：**
```python
app.mount("/api/outputs/generated", StaticFiles(directory=GENERATED_DIR), name="generated")
app.mount("/api/outputs/final_cuts", StaticFiles(directory=FINAL_DIR), name="final_cuts")
```
FastAPI `StaticFiles` 绕过了所有中间件和路由级认证。

**风险：** 目录列表开启时，任何人可遍历下载所有用户生成的图片和最终视频。

**优化建议：**
1. 移除 `StaticFiles` 挂载，改用路由方式提供文件：
   ```python
   @router.get("/outputs/generated/{filename}")
   async def get_generated(filename: str, user=Depends(get_current_user)):
       # 校验该文件属于当前用户（通过 session_id 反查）
       # 返回 FileResponse
   ```
2. 或至少关闭目录列表（`StaticFiles(directory=..., html=False)`），但这只是 obscurity，不是真正的安全
3. 长期方案：将生成文件存储到对象存储（S3/OSS），通过预签名 URL 提供限时访问

## 三、HIGH 级别问题与优化方案

### 问题 5：CORS 全开放（main.py 第 161 行）

**现状：** `allow_origins=["*"]`

**优化建议：**
1. 开发环境保留 `"*"`，生产环境改为白名单：`os.getenv("ALLOWED_ORIGINS", "http://localhost:8000").split(",")`
2. 如果前后端同域部署，可以完全移除 CORS 中间件

### 问题 6：资源所有权未校验（跨用户访问）

**现状：** 即使某些路由加了 `Depends(get_current_user)`，也只验证了"已登录"，没有验证"当前用户是否拥有该资源"。

**影响范围：**
- `assets.py` 的 `/file/{name}` 完全公开，按文件名直接返回，无任何校验
- `uploads.py` 的 `/assets/{aid}/raw` 遍历所有用户目录查找资源（信息泄露）

**优化建议：**
1. 所有资源访问端点统一模式：`router.get("/{resource_id}", user=Depends(get_current_user))`
2. 在 storage 层增加 `owns_resource(user_id, resource_type, resource_id)` 方法
3. `assets.py` 的 `/file/{name}` 必须校验：文件名中的 session_id → 反查 session 的 user_id → 与当前用户比对
4. `uploads.py` 的 `/raw` 端点删除跨用户遍历逻辑，改为：传入 user_id → 仅在该用户目录下查找 → 找不到则 404

### 问题 7：缓存接口公开（main.py）

**现状：** `GET /api/cache`、`DELETE /api/cache`、`DELETE /api/cache` 完全公开

**优化建议：**
1. 添加 `Depends(get_current_user)` 或 `Depends(_require_owner)`
2. 缓存清理应该是 owner 管理操作或每个用户只能清自己的缓存

### 问题 8：Agent ASR 接口开放

**现状：** `POST /api/agent/asr` 无任何认证

**优化建议：**
1. 至少添加 `get_current_user_optional`，未登录时限制调用频率
2. 已登录用户按 quota 限制

## 四、MEDIUM 级别问题与优化方案

### 问题 9：前端两套 API 函数不统一

**现状：**
- `NianAuth.fetch()` — 自动携带 Bearer token，401 自动登出
- `NN.apiGet()` / `NN.apiPost()` / `NN.apiUpload()` — 不携带认证头

**优化建议：**
1. 统一为 `NN.fetch()`，内部自动携带 token（如果已登录）
2. 废弃 `NianAuth.fetch()`，避免混淆
3. 增加 `NN.requireAuth()` 工具函数，未登录时跳转登录页

### 问题 10：无速率限制

**现状：** 登录、上传、API 调用均无速率限制

**优化建议：**
1. 登录接口：使用 `slowapi` 或自定义中间件，限制 5 次/分钟/IP
2. 文件上传：限制大小 + 频率
3. LLM 调用：按用户做 quota 控制（可结合 session 中的调用计数）

### 问题 11：无审计日志

**优化建议：**
1. 关键操作（登录、删除、admin 操作、数据导出）写入审计日志
2. 日志格式：`timestamp | user_id | action | resource | ip | result`
3. Admin 后台增加审计日志查看入口

## 七、架构建议总结

1. **统一认证中间件**：将认证从各路由手动 `Depends(get_current_user)` 改为路由注册时的自动注入，按模块/前缀配置认证策略
2. **资源所有权模型**：所有数据对象（Session、Memorial、Asset、Pipeline Output）必须有 `owner_id` 字段，访问时统一校验
3. **配置集中化**：所有密钥、URL、超时时间从 `config.py` 统一读取，禁止代码中硬编码
4. **安全测试纳入流程**：每次新增路由时， checklist 确认：是否需认证？是否校验所有权？是否限制速率？是否记录审计？
